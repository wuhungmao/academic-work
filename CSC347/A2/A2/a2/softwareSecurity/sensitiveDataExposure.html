# FIX OWASP A6: SENSITIVE DATA EXPOSURE

The Vulnerability

  • Brief explanation: Exposing sensitive data like user password, credit card info, health records unintentionally. This is due to weak security measures, wrong configuration.
  • Example code etc.: $dbconn = pg_connect_db(); # FIX OWASP 2013 A1: SQL Injection, use prepared statements $query = "SELECT id, username, firstName, lastName, passwd FROM account WHERE username=$1 AND passwd=$2"; $result = pg_prepare($dbconn, "", $query); $result = pg_execute($dbconn, "", array($user, $password));
  • How attacker exploits this: The attacker could use SQL injection or other methods to retrieve sensitive data like user password from the database. if the passwords are stored in plaintext, the attacker could easily get all user passwords. If the passwords are hashed but without salt, the attacker could use rainbow table to crack the hashes and get the original passwords.
  • Impact: CIAaa and some details Confidentiality: retrieve sensitive data from the database. Integrity: modify or delete data in the database. Availability: delete all the data in the database. Authentication: bypass authentication and login as another user once knowing password of other user. Authorization: gain unauthorized access to data.

The Fix

  • Explain the fix: Prof told me we can assume the passwords stored in the database is hashed already. So I simply use password_verify to compare the hashed password stored in the database with the user input password. As for using https instead of https, I generate a self-signed certificate and configure apache to use https. Please see apache.crt and apache.key and default-ssl file for details.
  • How the fix resolves the issue: Even if the database info is leaked because of sql injection or other method, the attacker could not get the plain user password.
